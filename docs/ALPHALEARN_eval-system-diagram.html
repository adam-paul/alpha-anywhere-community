Content Moderation Eval System

Autonomous optimization of moderation prompts via Karpathy Loop

System Overview

The full system has three connected cycles: the optimization loop (agent experiments overnight), the deploy path (human reviews and ships), and the production feedback flywheel (real usage grows the corpus). Phase 1 implements the optimization loop. Phase 2 adds the feedback flywheel.

The Optimization Loop (Detail)

A single experiment cycle. The agent modifies the Gemini classification prompt or the tunable parameters (temperature, per-category OpenAI thresholds), runs the full eval corpus through the production moderation pipeline, and keeps or discards based on the composite metric. Each cycle takes ~2-3 minutes. The agent runs ~20-30 experiments per hour.

Single Experiment Cycle
%%{init: {'theme': 'dark', 'themeVariables': { 'fontSize': '14px' }}}%%
flowchart TB
    START(["Start experiment"]) --> READ["Read current prompts\n+ recent misclassifications"]
    READ --> HYPO["Hypothesize a change\n(e.g. 'add coded Snapchat examples')"]
    HYPO --> MODIFY["Modify optimization targets"]

    MODIFY --> PROMPT["about_me.txt\nchat_message.txt"]
    MODIFY --> PARAMS["optimization_surface.py\ntemperature · per-category thresholds"]

    PROMPT --> COMMIT["Git commit\nwith description"]
    PARAMS --> COMMIT

    COMMIT --> EVAL["Run eval harness\n(~400 cases × Gemini + OpenAI)"]

    EVAL --> GEMINI["Each case:\nGemini classifies\n(uses modified prompt)"]
    EVAL --> OPENAI["Each case:\nOpenAI classifies\n(fixed API, per-category thresholds)"]

    GEMINI --> MERGE["Merge results\n(either can veto)"]
    OPENAI --> MERGE

    MERGE --> SCORE["Compute metrics\nprecision / recall / F1\nper category"]
    SCORE --> COMPOSITE["Composite score\n(severity-weighted F1)"]
    COMPOSITE --> CONSTRAINTS{"Hard constraints?"}

    CONSTRAINTS -->|"self_harm recall ≥ 0.99\npii recall ≥ 0.95\nharmful recall ≥ 0.92\nclean recall ≥ 0.85"| CHECK{"Score\nimproved?"}
    CONSTRAINTS -->|"ANY violated"| DISCARD

    CHECK -->|"Yes"| KEEP["✓ KEEP\nBranch advances\nNew baseline"]
    CHECK -->|"No"| DISCARD["✗ DISCARD\ngit reset --hard HEAD~1"]

    KEEP --> LOG["Log to results.tsv"]
    DISCARD --> LOG
    LOG --> CONVERGE{"15 consecutive\ndiscards?"}
    CONVERGE -->|"No"| READ
    CONVERGE -->|"Yes"| STOP(["Stop — converged"])

Optimization Surface

The agent has a deliberately narrow modification surface. It can only change 3 files — 2 prompt files and 1 parameter file. Everything else (the moderation service, the eval harness, the scoring engine, the corpus, escalation rules) is fixed.

Production Feedback Flywheel (Phase 2)

Once alpha testing generates real traffic, admin review decisions become labeled training data. Dismissed flags = false positives. Confirmed flags = true positives. Model disagreements surface ambiguous cases worth labeling. The corpus grows from real usage.

How Production Data Enters the Corpus
